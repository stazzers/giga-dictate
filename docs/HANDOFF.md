## Исправление остановки диктовки — 3.0.6

После пользовательского сбоя снят живой нативный стек 3.0.5 (`build/dictation-hang-3.0.5.sample.txt`). Сессия 7 зависла в `FinishStoppingStream → AudioOutputUnitStop → CoreAudio StopIOProc`; другой IO-поток ждал mutex в `startStopCallback → AudioUnitGetProperty`. `recorder.stop()` не вернул полный PCM, watchdog оставил предпросмотр для меню, а нативный вызов продолжал удерживать микрофон. Повторная вставка сессии 8 завершилась, но не снимала нативный замок.

**Текущая схема:** GUI создаёт `AudioRecorder(stream_factory=ProcessInputStream)`. Каждая запись использует новый дочерний процесс `giga_dictate.audio_worker` через bundle launcher. PCM передаётся по анонимному бинарному pipe без файлов. `finish_capture()` дожидается FIFO-маркера хвоста, отделяет массив и передаёт его ASR до нативного закрытия. `close()` подтверждает выход ребёнка; при зависании завершается только ребёнок. В нём есть собственный watchdog остановки и потери родителя, чтобы выход приложения не оставлял захват-сироту. Схему «приостанавливать и повторно использовать InputStream» для диктовки не возвращать.

Watchdog очистки не отменяет уже переданный полный ASR. Неисправная/отменённая Future вставки завершает сессию с сохранением текста; retry не захватывает микрофон. `tests/test_process_audio.py` выполняет реальные IPC/terminate/kill/wait с подставным устройством, без живого микрофона. `test_audio_responsiveness.py` покрывает полный результат → сбой вставки → retry → следующий старт и задержку закрытия после передачи аудио. Новые модули: `process_audio.py`, `audio_worker.py`. Захват микрофона встречи пока остаётся прежним `MicrophoneStream`.

3.0.6 установлена штатно поверх 3.0.5, настройки и кэш сохранены. Резервная копия: `build/giga-v3.0.5-backup-o77pwogx/GigaDictate.app`. Журнал: `build/dictation-release-install.json`; установщик именно этой версии: `build/install_dictation_release.py`. Оба полных набора по 223 теста прошли без пропусков (`build/dictation-native-tests.log`, `build/dictation-packaged-tests.log`). CLI-проверка разрешения дала `notDetermined`, поэтому реальный захват не начинался. Инструмент управления интерфейсом завершился по тайм-ауту; далее пользователь явно запретил доступ. Последняя проверка запуска дала `Ready for dictation`; в журнале также был запрос Accessibility. Учитывать отказ пользователя, не пытаться выдать доступ автоматически.

## Что сделано

### 3.0.0–3.0.1: встречи и обычная диктовка

Добавлены потоковые источники микрофона и системного звука через ScreenCaptureKit/PyObjC, общая временная шкала, ресемплинг, Silero VAD ONNX, CAM++ ONNX, очередь с явным завершением при переполнении и непрерывный ASR через существующий GigaAM. Минимальная macOS — 14.0.

Добавлены управление сессией, HUD с таймером и остановкой, окно результата, правка имён/автора, копирование, `.md`/`.txt`, Sharing в «Заметки», потоковое сохранение WAV/M4A по выбору. Работают частичный результат и обработка отказов источников. Режимы диктовки и встреч взаимно исключаются.

В 3.0.1 исправляли пустой вход обычной диктовки после встречи. Тогда поток закрывался после каждой диктовки. **Актуальная схема жизненного цикла изменена в 3.0.3**, см. ниже; старое описание в истории не является текущим требованием.

### 3.0.2: удаление голосового профиля

Удалены запись/хранение/распознавание профиля владельца, калибровка и роль «Вы». Сохранены нумерация, переименование и ручные исправления. CAM++ остаётся для разделения людей внутри текущей встречи; постоянный профиль не создаётся.

### 3.0.3: зависание при остановке диктовки и ложные спикеры

Пользователь сообщил о зависании диктовки и разделении одного голоса на трёх участников. Журнал обрывался при остановке после сообщения восстановления громкости, до ASR. Стека уже остановленного процесса нет: конкретная зависшая нативная функция не установлена.

Нативное управление микрофоном и громкостью перенесено из AppKit в последовательный daemon-поток `AudioExecutor`. Добавлены тайм-аут 5 секунд, восстановление имеющегося preview-текста и блокировка новых аудиосессий до возврата зависшей операции. При остановке сначала приостанавливается вход, текст передаётся на ASR, затем восстанавливается громкость. При зависшем завершении исключён повторный блокирующий `Pa_Terminate` на главном потоке.

**Исторический жизненный цикл 3.0.3–3.0.5, заменённый в 3.0.6:** между обычными диктовками InputStream приостанавливался и повторно использовался; перед встречей полностью закрывался на аудиопотоке. В 3.0.6 диктовка каждый раз использует новый дочерний процесс и полностью освобождает его после записи; см. раздел выше.

Диаризация исключает VAD-паузы из эмбеддингов, использует окна 2 секунды с шагом 0,5 секунды и требует три согласованных окна для нового участника. Добавлена ограниченная галерея вариантов голоса, разрешение предварительных ID и удаление пустых участников из результата.

### 3.0.4: финальное уточнение неуверенных реплик

Пользователь предоставил стенограмму 50-секундного теста: начало помечено «Спикер 1», несколько следующих его реплик — «Спикер не определён», длинный второй голос распознан как «Спикер 2». Исходного звука для повторения именно этого теста в распоряжении агента нет.

Добавлено `OnlineDiarizer.refine()`: после обработки хвоста неопределённые реплики сопоставляются с фиксированной галереей подтверждённых голосов за всю встречу. Для ранних/коротких фраз временно сохраняются `SpeakerEvidence`: до восьми 192-мерных векторов на реплику, веса и длительность речи. Аудио в этих сводках отсутствует; после прохода сводки освобождаются, в `MeetingResult` не попадают.

Речь от 0,6 секунды может оставить вектор для финального уточнения, даже если её не хватило для потокового назначения. Для короткой речи порог строже. Соседние реплики могут оцениваться вместе только при акустическом сходстве. Требуются преимущество перед вторым кандидатом и согласие большинства окон. Слабые назначения не обучают галерею, не создают новых людей и не сливают подтверждённых спикеров. Ручные исправления имеют приоритет. Текст повторно не распознаётся. При ошибке уточнения возвращается доступная стенограмма с контролируемым сообщением.

Это повторное сопоставление с подтверждёнными участниками, а не полная глобальная перекластеризация всех голосов. Если информации недостаточно или кандидаты одинаково похожи, «Спикер не определён» сохраняется. Полностью исключить ошибки по одному микрофону не обещаем.

При тестировании встроенным Python сначала импортировать модули из bundle, затем загружать тесты из проекта: иначе тестовый путь может подменить сборку исходниками. Пример:

```bash
GIGA_UI_TESTS=1 GIGA_MODEL_TESTS=1 GIGA_NATIVE_AUDIO_TESTS=1 \
  './GigaDictate.app/Contents/MacOS/GigaDictate' -c '
import importlib, pkgutil, unittest
from pathlib import Path
import giga_dictate
assert giga_dictate.__version__ == "3.0.4"
for module in pkgutil.iter_modules(giga_dictate.__path__, "giga_dictate."):
    if module.name != "giga_dictate.main":
        importlib.import_module(module.name)
project = Path.cwd().parents[2]
suite = unittest.defaultTestLoader.discover(str(project / "tests"), top_level_dir=str(project))
result = unittest.TextTestRunner(verbosity=0).run(suite)
raise SystemExit(not result.wasSuccessful())
'
```

Не удалять весь `build/`: там находятся модели, результаты проверок и резервные копии установленных приложений. Исправленный `create_dmg.sh` использует отдельный рабочий каталог. Для повторной установки сначала завершить приложение штатно, подготовить и проверить staging-копию, сохранить предыдущий bundle, заменить приложение и проверить запуск. Существующий `build/install_speaker_refinement.py` — локальный журналируемый установщик именно 3.0.4, а не универсальный механизм автообновлений.
