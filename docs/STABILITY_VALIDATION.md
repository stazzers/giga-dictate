# GigaDictate 2.0.3 — стабилизация и проверка

Дата: 13 ноября 2026. Базовая версия для сравнения: `d6c698a`.
Проверенная конфигурация: **Apple M2, 8 ГБ RAM, macOS 27.0.1, Metal/MPS**.

## Что изменилось

- Один цикл `idle → recording → transcribing → inserting → idle/error`. Повторный запуск во время обработки не сбрасывает аудио. Ручное управление синхронизировано с горячей клавишей.
- Результаты, предпросмотр и таймеры защищены поколением сессии. Завершение старой задачи не скрывает новый HUD.
- Вставка выполняется без `sleep` в главном потоке. Физические модификаторы ожидаются максимум секунду; перед отправкой проверяются Accessibility, активное приложение и владение буфером.
- `TextInserter.insert_text()` теперь возвращает `Future[InsertionResult]`: `event_posted` либо `error` с технической причиной. Это отправка события, а не подтверждение со стороны поля ввода. События помечены и игнорируются собственным обработчиком горячей клавиши.
- Буфер восстанавливается через 750 мс после отпускания синтетической V. Сохраняются все доступные элементы и форматы, включая двоичные данные. Восстановление отменяется при изменении `changeCount`; если снимок буфера недоступен, операция завершается до его перезаписи.
- Используется современный `NSPasteboardTypeString`; добавлены маркеры Transient, AutoGenerated и Concealed. Их действие зависит от поддержки сторонним менеджером буфера.
- Последняя непустая транскрипция хранится в памяти пять минут, включая случаи отправленного, но проигнорированного `Cmd+V`. В меню есть повторная вставка, копирование и очистка. Повторная вставка выполняется только явно; новое приложение принудительно не активируется.
- HUD — неактивирующий `NSPanel` с CanJoinAllSpaces, FullScreenAuxiliary и именованным уровнем NSStatusWindowLevel. При смене Space/экранов активный HUD размещается заново; неактивный остаётся скрытым.
- HUD сразу появляется около мыши. Accessibility уточняет положение в отдельном потоке с тайм-аутом 80 мс на запрос. Устаревшие ответы отбрасываются; длинный текст ограничен последними строками и высотой 160 pt.
- Предпросмотр сохраняет завершённые фрагменты, распознавая только изменяемый хвост до 20 секунд. Аудиоснимок готовится вне главного потока и содержит только незавершённые данные. Финальный проход остался независимым, в float32.
- Завершение приложения очищает текст, отменяет задачи и таймеры, восстанавливает громкость и закрывает микрофон. Ошибка одного компонента не прерывает остальные этапы очистки.

## Автоматические проверки

Итог: **104 теста прошли встроенным Python окончательной сборки `.app`, включая нативные окна и приватный NSPasteboard**. Обычный запуск из исходников: 72 пройдено, 32 нативных теста пропущены до явного включения. Подпись окончательной сборки проверена через `codesign --verify --deep --strict`; упакованные модули побайтово совпадают с исходниками.

Обычные тесты не используют микрофон, звук, системный буфер, реальные события клавиатуры или пользовательские файлы конфигурации:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Для нативных окон нужен доступ процесса к оконной системе macOS:

```bash
GIGA_UI_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Нативный набор проверяет создание и размещение панели, настройку Spaces/fullscreen, отсутствие захвата фокуса, защиту от старого таймера, ограничение текста и восстановление нескольких форматов настоящего **приватного** тестового NSPasteboard. Общий буфер пользователя не затрагивается. Смена настоящих Spaces этими тестами не выполняется.

Дополнительно проверяются 100 последовательных транзакций вставки с подменёнными клавиатурными событиями, ошибки записи/отправки, удержание модификаторов, смена приложения, изменение буфера пользователем, истечение срока хранения, отмена и очистка после ошибок. Эти 100 транзакций не заменяют 100 реальных диктовок в сторонних приложениях.

## Бенчмарк распознавания

Воспроизводимая команда с уже загруженными весами:

```bash
.venv/bin/python scripts/benchmark_preview.py --baseline-ref d6c698a
```

Скрипт использует `example.wav`, повторённый до пяти минут, блокирует сетевые загрузки и не выводит распознанный текст. JSON сохраняется в `build/preview-benchmark.json`.

Сравнивались обновления по растущим снимкам 1, 5, 10, 20, 40, 60, 90, 120, 180, 240 и 300 секунд. Это один локальный прогон, а не имитация полной сессии с частотой 350 мс; исходная и новая версии используют одну модель последовательно, поэтому возможен эффект прогрева.

| Длина аудио | Предпросмотр до / после | Финальный проход до / после | Итоговый текст |
| --- | --- | --- | --- |
| 10 секунд | 129,54 / 109,78 мс | 114,67 / 113,80 мс | Совпадает |
| 60 секунд | 787,81 / 306,96 мс | 625,21 / 627,92 мс | Совпадает |
| 300 секунд | 3137,02 / 708,27 мс | 3145,82 / 3135,09 мс | Совпадает |

В обновлении на пятой минуте число вызовов модели сократилось с 19 до 4: обрабатывается накопившийся после предыдущего снимка хвост, завершённая история повторно не распознаётся. При частых обновлениях тестами подтверждён один вызов для изменившегося хвоста до следующей границы фрагмента. Пиковый RSS общего процесса — около 1,36 GiB; отдельных замеров памяти каждого варианта и замеров энергопотребления нет. Качество распознавания на отдельном размеченном корпусе не оценивалось.

## Сборка и оставшаяся ручная приёмка

`bash scripts/create_app.sh` создаёт локальный `GigaDictate.app` версии 2.0.3. Проверяются подпись вложенных компонентов, arm64-запуск, автономный Python и отсутствие путей разработчика. Проверки запускаются также встроенным интерпретатором приложения. Установленный экземпляр в `/Applications` автоматически не заменяется.

Тестовый запуск новой локальной сборки сообщает `AXIsProcessTrusted() == False`. Разрешения автоматически не менялись. Полную автовставку в сторонние приложения необходимо проверить из разрешённого macOS установленного экземпляра.

Остаётся выполнить и записать результаты:

1. По 25 коротких диктовок в браузере, редакторе, мессенджере и терминале; оба режима клавиши, русская и английская раскладки. Убедиться в отсутствии пропусков и дублирования.
2. На трёх обычных Spaces начать запись до и после перехода; повторить с fullscreen, Mission Control и отключённым предпросмотром. Проверить видимость HUD и сохранение фокуса в поле.
3. Проверить внешний монитор слева, справа и выше встроенного, отключение монитора во время записи и режим отдельных Spaces на экранах.
4. При обработке переключить приложение: текст должен попасть в активную цель на момент начала вставки. При смене приложения уже внутри транзакции должна появиться ошибка с доступным повтором.
5. Во время восстановления буфера скопировать новые данные; они должны сохраниться. Проверить исходный буфер с изображением, RTF и несколькими элементами.
6. Проверить снятые разрешения микрофона/Accessibility, удержание Command, восстановление результата, сон/пробуждение и обновление установленного приложения. После истечения пяти минут команды восстановления должны отключиться.
7. С отключённой сетью проверить запуск с кэшированными весами и короткую/длинную диктовку.

M1, M3, M4, macOS 14–26, внешние мониторы и реальные переключения Spaces в этой сессии не проверены. Поддержка macOS 14 и прежний идентификатор приложения сохранены; подтверждение всей матрицы требует соответствующих устройств.
