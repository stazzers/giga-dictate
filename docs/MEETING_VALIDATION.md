# Проверка Meeting & Conversation Mode — 3.0.0

Дата: 13 ноября 2026. Устройство: **Apple M2, 8 ГБ RAM, macOS 27.0.1, Metal/MPS**.

## Исправление диктовки 3.0.1 — 14 ноября 2026

После проверки встреч пользователь сообщил, что обычная диктовка перестала получать звук. Журнал подтвердил: первые диктовки после запуска давали распознанный текст, затем несколько сессий длительностью в несколько секунд завершились с `duration_s=0.000`. Во всех проблемных случаях использовалось возобновление прежнего потока (`stream resumed`), то есть до ASR вообще не доходили аудиосэмплы.

В 3.0.1 обычная диктовка полностью закрывает PortAudio/CoreAudio stream при остановке и создаёт новый на следующем старте. Перед встречей или калибровкой также освобождается рекордер диктовки. Состояние и аудиобуфер очищаются под согласованными блокировками; при ошибке `stop()` всё равно выполняется `close()`. Для пустого входа добавлено сообщение о том, что микрофон не передаёт данные.

Добавлены шесть проверок, включая последовательность «диктовка → MicrophoneStream встречи → диктовка» на модели устройства, инвалидирующего старый приостановленный поток. До исправления эта последовательность возвращала пустой массив после встречи. **Все 154 теста прошли встроенным Python сборки 3.0.1 с нативными окнами, AAC и локальными моделями.** Это регрессионные проверки с синтетическими данными, а не новая запись живого голоса.

3.0.1 установлена поверх 3.0.0 в `/Applications/GigaDictate.app` и перезапущена; модель загрузилась на MPS. Подпись проверена, установленные `.py` совпадают с исходниками. Настройки, модельный кэш и голосовой профиль не заменялись. Резервная копия 3.0.0: `build/giga-v3.0.0-backup-6a7nbe65/GigaDictate.app`; сведения об обновлении: `build/dictation-fix-install.json`. После перезапуска приложение сообщило об отсутствии Accessibility; для горячей клавиши нужно снова выдать «Универсальный доступ».

## Итог автоматической проверки

**148 тестов прошли встроенным Python окончательной локальной сборки `.app`, без пропусков.**

Включены `GIGA_UI_TESTS=1`, `GIGA_MODEL_TESTS=1`, `GIGA_NATIVE_AUDIO_TESTS=1`. Проверены существующий режим диктовки, вставка, clipboard/ducking/HUD, новая сессия встречи, VAD, диаризация, калибровка, очередь, экспорт, CoreMedia planar/interleaved PCM, нативные окна, редактирование автора реплики и AAC/M4A. Нативные тесты не записывают живой микрофон/систему и не используют общий буфер пользователя. Сообщения `insertion_failed` и `shutdown_cleanup_failed` возникают в тестах с намеренно внедрёнными отказами.

При запуске тестов предварительно импортировались модули `giga_dictate` из `GigaDictate.app/Contents/Resources`, затем загружался набор тестов проекта. Путь пакета подтверждён выводом встроенного интерпретатора. После проверки все упакованные `.py` побайтово совпадают с исходниками.

`codesign --verify --deep --strict GigaDictate.app` проходит. Bundle ID сохранён: `com.salute.gigadictate`; версия — `3.0.0`; минимальная macOS — `14.0`. Сборка локальная, с ad-hoc подписью.

Версия 3.0.0 установлена поверх 2.0.3 в `/Applications/GigaDictate.app` и запущена. Предыдущий экземпляр завершён. Проверены версия установленного bundle, подпись и новый запущенный процесс из `/Applications`; GigaAM загрузился на MPS, журнал сообщил `Ready for dictation`. Конфигурация и кэш моделей не заменялись. Резервная копия предыдущего приложения находится в `build/giga-v3-backup-auajfqx1/GigaDictate.app`; сведения об установке — в `build/local-install-backup.json`.

## Модели

Подготовлены Silero VAD ONNX и CAM++ ONNX. Загрузки исходников/checkpoint проверены закреплёнными SHA-256. ONNX сравнен с PyTorch на длинах **99, 150 и 345 mel-кадров**. Исправлена совместимость знаменателя `AveragePool` при `ceil_mode` для коротких окон. Два независимых экспорта дали одинаковые контрольные суммы всех поставляемых файлов:

| Файл | SHA-256 |

| `campplus.onnx` | `a3174d957d8f87bac0cafac133de498f9d5c71505d47078cfaa2148467f92531` |

FBank из kaldi-native-fbank дополнительно сравнен с `torchaudio.compliance.kaldi.fbank` на фрагменте `example.wav`: формы совпали, максимальное абсолютное расхождение после CMN около `0.00042`.

## Ускоренное воспроизведение часового аудио

Команда с уже кэшированными весами GigaAM:

```bash
.venv/bin/python scripts/benchmark_meeting.py \
  --seconds 3600 --mode room \
  --output build/meeting-room-hour-benchmark-mps.json
```

Выполнен полный пайплайн **нормализация → Silero → CAM++ → кластеризация → GigaAM → результат**. Вместо живого захвата использовался повторённый `example.wav`. Сетевые загрузки запрещены; аудио и распознанный текст не сохранялись и не выводились.

| Метрика | Результат |
| --- | --- |
| Длительность входного аудио | 3600 с |
| Время обработки | 226,407 с |
| CPU time процесса | 185,307 с |
| Real-time factor | 0,0629 |
| Пиковый RSS процесса | 1 406 812 160 байт, около 1,31 GiB |
| Максимальная очередь микрофона | 90,016 с |
| Ошибки сессии | 0 |
| Реплики | 320 |
| Назначенные спикеры | 1 |
| Реплики с неопределённым автором | 1 |

Генератор ускоренного воспроизведения применяет backpressure около 90 секунд; реальный capture-callback никогда не ожидает освобождения очереди. Поэтому этот прогон подтверждает длительную обработку и ограничение буфера, но **не является часовым живым созвоном**, нагрузочным тестом всех аудиоустройств или измерением батареи. Пиковый RSS включает GigaAM, ONNX Runtime, Python и кэши MPS. Из него нельзя вывести отдельный расход памяти диаризации.

Дополнительно успешно проверены короткий двухканальный онлайн-прогон и пятиминутный комнатный прогон. Точные показатели каждого отдельного запуска находятся в `build/meeting-*-benchmark*.json`; они зависят от прогрева и конфигурации порогов на момент прогона.

## Оставшаяся приёмка

У тестового экземпляра `CGPreflightScreenCaptureAccess()` возвращает `False`, авторизация микрофона — `Denied`. Разрешения не менялись и живой захват не выполнялся.

До релизной приёмки необходимо проверить установленный и разрешённый macOS экземпляр:

1. Совместный захват с Zoom, Telegram и браузерными Meet/Телемост, с проверкой обоих каналов и часовой длительности.
2. Реальный комнатный разговор 2–6 людей, калибровку владельца и его новые фразы.
3. Наушники/Bluetooth/динамики, смену маршрута и отключение микрофона, TCC-отказ/отзыв разрешения и сон.
4. Fullscreen/Spaces, внешние мониторы и перенос HUD после отключения экрана.
5. macOS 14 и другие поколения Apple Silicon.
6. Независимый размеченный русскоязычный корпус: WER, DER, ложное узнавание владельца и пропуски его голоса. Данные для настройки порогов должны отличаться от итоговой проверки.

В репозитории нет такого корпуса, поэтому точность диаризации и узнавания владельца пока не аттестована. Пороги остаются начальными; предусмотрена ручная правка подписей. Наложенные голоса в одном канале не разделяются, эхоподавления динамиков нет. Расход батареи и температура не измерялись.
